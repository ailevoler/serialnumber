SurgeBox V5 - Client Accounts + Payment Third-Party Integrations (surge-box.org)
================================================================================

DEPLOY (Hostinger)
1. hPanel: add domain surge-box.org and subdomain portal.surge-box.org, BOTH
   pointing to the SAME folder (this build).
2. Database:
   - NEW / EMPTY database (surge-box.org): import
     database/surgebox_v5_full_install.sql (all tables + starter data only,
     Admin login admin@surgebox.com with your current SurgeBox password).
   - EXISTING SurgeBox database with data: import
     database/migration_v5_client_gateways.sql (safe to re-run; also adds the
     missing portal_reset_* columns used by Portal "Forgot Password").
3. .env (see .env.example):
     APP_URL=https://surge-box.org
     ADMIN_URL=https://surge-box.org
     PORTAL_URL=https://portal.surge-box.org
     APP_SANDBOX_MODE=0            (1 = only PayMongo sk_test_ keys allowed)
     APP_KEY=<already generated in the shipped .env - NEVER change it after
              credentials are saved>
     DB_* for the surge-box.org database

HOST ROUTING
- portal.surge-box.org  -> client login, pre-registration, pre-onboarding,
  client dashboard, My QR Ph, Settlement. Staff pages redirect to portal login.
- surge-box.org         -> Admin. Portal pages redirect to portal.surge-box.org.
- /api/* and webhooks work on both hosts. Emails (verify, reset, activation)
  now link to PORTAL_URL.

ADMIN
- Manage: create Client Accounts as before (+ optional Client Code, e.g. PCEC,
  PHILRADS) and approval badge.
- Payment Providers (new menu): PayMongo (Priority, Live), Nationlink,
  OptekPay (Pay8), SwiftPay (credentials only for now). Enable/disable,
  set priority, overview of every client's credentials.
- Client page > "Client Approval & Payment Credentials":
    * Approve (all 7 merchant documents submitted) or
      "Approve - Documents to Follow". Credentials are locked until approved.
      Also available on Pre-Registrations. Uploading the remaining documents
      later flips the client to "Approved" automatically.
    * Per client + provider: Environment (test/live), Status, API keys
      (encrypted AES-256-GCM), unique Webhook URL, "Test" and
      "Register Webhook" (auto-creates the PayMongo webhook for payment.paid,
      payment.failed, qrph.expired and stores the signing secret).
    * Fees/MDR: Fixed (e.g. PHP10), Percentage, Fixed + Percentage, optional
      min / max cap; "Deduct from settlement" OR "Do not deduct - bill
      separately" (client keeps the full processed amount).
    * "Also credit SurgeBox wallet" - only when funds settle to a
      SurgeBox-controlled account (default OFF: funds go to the client's own
      PayMongo account).
- Client Fees (new menu): per-client Deducted / Unbilled / Billed / Paid /
  Waived fees; mark Billed / Paid / Waived; open the client's Settlement.

CLIENT PORTAL
- Dashboard onboarding: Pre-Registered > Email Verified > Requirements >
  Admin Approval > Payment Integration.
- My QR Ph (once approved + an Active PayMongo gateway):
    * Store Front QR Ph (static, reusable) - multiple, each with its own
      Label/Name; per-QR totals; download poster; enable/disable; edit label.
    * Dynamic QR Ph - exact amount, description, reference, 15m-2h validity;
      live "Waiting for payment" screen that turns to "Payment received".
    * TEST-mode gateways get "Simulate Payment" for demos.
- Settlement Dashboard: Gross, Fees Deducted, Fees Billed Separately,
  Net Settlement (daily + per transaction), CSV export.

PAYMONGO NOTES
- Static QR: POST /v1/qrph/generate (kind=instore). Dynamic: Payment Intent
  (qrph) + Payment Method (qrph) + attach -> next_action.code.image_url.
- QR Ph must be activated on each client's PayMongo account.
- Payment matching: dynamic by payment_intent_id, static by
  source.provider.code_id. Idempotent on the PayMongo payment id.
- Webhook URL per client: /api/paymongo_webhook.php?t=<token>

FIXES FOUND DURING TESTING
- Missing sb_organization.portal_reset_token_hash / portal_reset_expires_at
  (Portal Forgot Password would crash) - added by the migration.
- api/static_qr.php crashed when "provider" was omitted (null insert).
- Server error log now includes the exception message.

V5.1 - Fees visible to Admin only
- Clients (portal) and staff Managers/Viewers never see the SurgeBox fee/MDR.
  Collections are shown at their NET amount only: payer sends PHP1,010.00,
  fee PHP10.00 (Deduct from settlement) -> client sees PHP1,000.00 everywhere
  (Dashboard, Transactions, Settlement, QR totals, CSV exports).
- API responses for non-Admin sessions no longer include fee, fee mode,
  provider fee or the admin running-fee balance (was previously exposed).
- Admin still sees Gross / Fee / Net on the client page, Client Fees and
  Admin > client Settlement.

V5.2 - Client Portal login from Admin
- Manage > + Add new Organization now has "Client Portal Login": Portal
  Username (blank = the Email Address) + Portal Password (with Generate).
  After Create, the login details (link, username, password) are shown once
  with a "Copy Login Details" button to send to the client.
- Manage list shows "Portal" (login set) or "Set Portal Login" per client.
- Client page: "Client Portal Login" card moved to the top (link, username,
  status, last login) with "Set Up Portal Login" / "Manage / Reset Password".
- Setting a username without a password is now rejected (previously it
  created a login the client could never use).

V5.3 - Login fix
- Client (Portal) accounts that sign in on the staff login page are now sent
  to the Client Portal automatically instead of "Invalid credentials".
- REQUIRED .env for surge-box.org (blank values disable host routing, which
  made portal.surge-box.org open the STAFF login):
    ADMIN_URL=https://surge-box.org
    PORTAL_URL=https://portal.surge-box.org

V5.6 - Fee display + Recalculate Fees
- Admin tables (Dashboard, Transactions, Client page): "Amount" = net after
