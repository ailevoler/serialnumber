Ultimate App is a mobile-first super-app for Boracay. One PHP code base and one MySQL database serve five web applications: the customer app, the URide Driver App, the Merchant Portal, the Agents Portal and the Admin Panel.

Domain functions throw InvalidArgumentException for user-facing errors (shown as alerts) and other exceptions for system faults (logged, generic message shown). Every money change runs inside one InnoDB transaction.

2.3 Settings

  • Stored in app_settings (setting_key, setting_value, is_secret). Read with setting() / setting_int(); written with setting_save(), which records the admin and audit trail.
  • includes/settings.php holds the schema: type, limits and label for every key (e.g. uride.boat.per_km_centavos, cancel.ueat_pct).
  • Secret values (PayMongo and SUNIWAY keys) are encrypted with the key in config/app_secret.php. Back up that file with the site, or the secrets must be entered again.
  • Most settings are edited in Admin › Settings (Super Admin only): Payments, Charges & limits, Google Maps, URide.

2.4 File storage

Uploads are saved on disk, not in the database, with random names, and served only through access-checked PHP scripts (e.g. market-photo.php, admin/kyc-file.php). Images are re-encoded on upload, which strips EXIF/GPS data. To keep files safe across redeploys, copy config/storage.php.example to config/storage.php and point it to a folder outside public_html. Admin › System › Files & storage runs a write test and lists records whose files are missing.

3Money model and ledger

Two customer wallets, one rule: every money movement is posted to a balanced double-entry ledger in the same database transaction as the balance change.

Credits

The main in-app balance. 1 Credit = ₱1.00. Stored in users.credits (decimal pesos). Bought with QR Ph or at an MCTC top-up center; spent on every service. Ledger account user_credits:ID.

BCash

A separate peso wallet in boracay_cash_wallets.balance_centavos. Converted 1:1 from/to Credits with no fee; used for transfers, payments and currency exchange. Ledger account user_cash:ID.

3.1 Amounts

  • All new money columns are integer centavos (*_centavos). No floating-point arithmetic is used for money.
  • Percentages are computed with integer basis points and rounded once (e.g. commission intdiv(fare × bp + 5000, 10000)).
  • URide fares and rental prices are rounded up to the whole peso.

3.2 The ledger

ledger_post($pdo, $group, $event, $lines) inserts lines into ledger_entries. Each line is [account, debit, credit]. The function refuses any entry whose debits and credits differ, or that is zero. The group ties the lines to a business reference (e.g. a ride code, RF-… for a refund, CF-… for a cancellation fee).

3.3 Safety against double charging

  • Request keys. Booking and payment forms carry a random one-time key; replays return the original result instead of charging again.
  • Row locks. Balances, rides, orders and top-ups are read with SELECT … FOR UPDATE inside the transaction (e.g. first driver to accept wins).
  • Unique constraints. Payment IDs, references, receipt numbers per merchant and approval keys are unique in the database.
  • Webhooks are verified by signature and matched to the stored order (amount, currency, mode, session) before settling.

8Wallet, transfers and exchange

8.1 Buy Credits

  • QR Ph (PayMongo): in-app QR via Payment Intent (topup-qr.php), with hosted checkout as fallback. Credited only by a signed webhook (payment.paid or checkout_session.payment.paid) or by an authenticated status check that matches session, reference, mode and exact amount. QR expires after 30 minutes. A ₱5.00 service fee per top-up is configurable.
  • MCTC (cash): the customer shows a request QR at an MCTC top-up center (an approved merchant). The merchant scans it, enters a receipt number (unique per merchant) and confirms; Credits are added immediately and the cash becomes the merchant's MCTC due, deducted from the next payout.

8.2 BCash

  • Convert Credits ⇄ BCash 1:1, no fee, atomic with a unique request key.
  • Send / Receive / My QR: BCash QR codes (with the BCash logo) always send BCash; Credits QR codes always pay Credits. ₱1–₱10,000 per transfer, max 20 sends per hour, no fee.
  • When KYC is required for customers, unverified accounts cannot send Credits or BCash or use UCash In.

8.3 P2M and P2P payments

Scan QR detects merchant QR codes (UM-…, P2M) and person QR codes (UA-…, P2P). P2M shows the charge and total before paying, with Credits or BCash.

8.4 Currency exchange

  • USD/PHP is the main pair; about 20 more currencies can be enabled in Admin › ERP › Currency exchange. Each currency has its own wallet and decimals.
  • Rates: Frankfurter first, then currency-api, or a manual rate. Refreshed hourly (cron/fx-refresh.php). Exchanges pause if the rate is older than 24 h; an automatic rate outside ₱20–200 or more than 10% from the last one is refused.
  • Fees 0–5% for buy and sell (default 0.50% for USD, 1.00% for other currencies). The amount is locked to the rate shown.

10Identity: KYC, liveness and Face Login

10.1 KYC

  • Available to customers, merchants, drivers and agents: ID front and back, then a guided liveness selfie (look straight, left, right, up, down, blink), then review and send.
  • Face detection runs on the phone with MediaPipe. The side to turn to flashes red; correct poses turn green and capture automatically; wrong turns are counted and shown to Admin.
  • The "look straight" selfie is compared with the ID photo using face-api. The server re-checks the descriptor distance (default max 0.60) and refuses a mismatch.
  • Every submission is reviewed by a person in Admin › KYC verification: Approve, Ask to resubmit, or Reject. "Manual" submissions (no automatic check) need extra care.
  • Rules (Admin › KYC › Rules): merchants, drivers and agents need approved KYC before approval (on by default); customers only for sending money and UCash In (off by default).

10.2 Face Login (customers)

  • Set up in Profile: a short liveness check whose face must match the approved KYC face. The phone gets an HttpOnly, SameSite=Strict device key; only its SHA-256 is stored.
  • Login: the server issues random steps and a one-time code valid for 2 minutes, checks step order and timing, and compares the 128-number face descriptor (default max distance 0.45).
  • 5 wrong tries lock Face Login on that phone until a password login. Users can turn it off per phone or on all phones.
  • Face Login is a convenience login for the person's own phone, not a bank-grade identity proof. The password always works.
PrivacyOnly still photos (KYC) or 128 numbers (Face Login) leave the phone. Photos are re-encoded (no EXIF/GPS), stored with random names in storage/kyc/, and shown only to signed-in admins with KYC access. IP address and browser are recorded for audit.

  • Registration with selfie, license, vehicle (including Boat), plate or boat registration, documents; status Submitted → Under review / Needs info → Approved.
  • Online/offline toggle, live request feed with beep, accept/skip, navigation, trip steps, self-drive hand-over and return, fleet units, wallet with QR Ph / MCTC / BCash top-ups and payouts.
  • The app must stay open with location allowed to receive requests (browsers pause background GPS).

11.4 Agents Portal

  • Approved agents get a referral link (/register.php?ref=AG…), code and QR. Customers are tagged once at sign-up, for agents.earn_days (default 365).
  • Default rates: URide 2% of the fare, UEat 3% (earned after a 3-day hold), UPass/UGo/ULocal 5% (earned when completed). Paid by Ultimate App as an expense.
  • Master Agents and Sub-Agents (one level). Masters earn an override on top (default 0.5% URide/UEat, 1% bookings).

11.5 UBarangay

Permits paid with Credits, BCash or QR Ph, reviewed by the Barangay Officer, issued with a verification QR (/verify.php). Fees post to brgy_payable. Off by default.

13Deployment

13.1 Server requirements

  • PHP 8.1+ with PDO MySQL, cURL, GD (image re-encoding), OpenSSL, mbstring; outbound HTTPS.
  • MySQL 8 or MariaDB 10.x with InnoDB (tested on MariaDB 10.11).
  • HTTPS (needed for camera, GPS, PWA install and Apple sign-in).
  • Writable storage/ (or the folder in config/storage.php) and, once, config/.

13.2 Steps (Hostinger)

  1. Back up the database and the site files (including config/ and storage/).
  2. Import migrations in phpMyAdmin (13.3). Every migration is safe to run again.
  3. Upload the update zip (changed files only) or the full zip. Keep the live config/config.php, config/app_secret.php and storage/.
  4. Configure in Admin › Settings: PayMongo keys, Google Maps key, URide fares, payment methods, cancellation fees, SUNIWAY.
  5. Set the PayMongo webhook to https://YOUR-DOMAIN/webhook.php (events payment.paid and checkout_session.payment.paid).
  6. Add the cron job: php /home/<user>/public_html/cron/fx-refresh.php every hour.
  7. Smoke-test on real phones: booking, payment, driver app, merchant orders.

15Operations and known limits

15.1 Routine operations

  • Daily: process driver, agent and merchant payouts (mark paid with the transfer reference); resolve SUNIWAY "Needs checking"; review KYC and driver applications.
  • Weekly: check Admin › Finance reconciliation (wallets, escrow, MCTC dues); export reports.
  • Backups: database, config/ (especially app_secret.php) and the storage folder, together.
  • Rates and prices: starter fares, rental prices, deposits and listing prices are placeholders — confirm them with the LGU, TODA and partners.

15.2 Known limits

  • URide distances use straight line × road factor, not routed distance (this also applies to Boat routes).
  • UEat delivery is done by the restaurant; no rider dispatch yet.
  • Extending a running rental is not built in.
  • Liveness and Face Login run on the phone; every KYC is still reviewed by a person.
  • QR Ph and bank/e-wallet payouts are manual (Finance marks them paid); no automated payout provider is connected.
  • BCT, Buy BCT and Markets pages are "coming soon".
  • Stored-value and e-money rules (BSP Circular 1166) should be reviewed with counsel before BCash is offered as redeemable cash.
